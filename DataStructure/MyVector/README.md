# MyVector

## 개요

`MyVector<T>`는 연속된 메모리 공간을 사용하는 동적 배열입니다. 원소 수와 할당 용량을 별도로 관리하며, 공간이 부족해지면 더 큰 메모리를 확보한 뒤 기존 원소를 이동합니다.

단순 복사가 가능한 타입은 `memcpy`와 `memmove`를 사용하고, 그 외 타입은 생성자·소멸자와 이동 연산을 사용하도록 분기한 것이 구현상의 특징입니다. 복사 및 이동 생성자와 대입 연산자를 제공하여 컨테이너 자체의 값 복사와 소유권 이전도 지원합니다.

## 포함 기능

| 구분 | 메서드 |
| --- | --- |
| 생성 및 소유권 | `MyVector`, 복사/이동 생성자, 복사/이동 대입, 소멸자 |
| 상태 조회 | `size`, `capacity`, `data`, `empty` |
| 용량 관리 | `resize`, `reserve`, `shrink_to_fit`, `clear` |
| 원소 변경 | `push_back`, `pop_back`, `insert`, `erase` |
| 원소 접근 | `operator[]`, `front`, `back` |
| 분석 보조 | `set_growth_factor`, `linear_push_back` |

`set_growth_factor`와 `linear_push_back`은 용량 증가 정책에 따른 성능 차이를 확인하기 위한 비교용 기능입니다.

## 분석

### 연산 복잡도

| 연산 | 시간 복잡도 | 원인 |
| --- | --- | --- |
| `operator[]`, `front`, `back` | O(1) | 연속 메모리에서 주소를 직접 계산 |
| `push_back` | 평균 O(1), 최악 O(n) | 공간이 부족한 경우 전체 원소 재배치 |
| `pop_back` | O(1) | 마지막 원소만 제거 |
| `insert`, `erase` | O(n) | 삽입·삭제 지점 뒤의 원소 이동 |
| `reserve`, `shrink_to_fit` | O(n) | 새 메모리로 전체 원소 이동 |
| `resize` | O(n) | 크기 차이만큼 생성 또는 소멸하며 필요 시 재할당 |

### 용량 증가 정책

기본 `push_back`은 용량이 부족할 때 현재 용량에 증가 계수를 곱해 확장합니다. 기본 증가 계수는 `2`입니다. 반면 `linear_push_back`은 용량을 매번 `10`씩 늘립니다.

```text
원소 수 증가  ─────────────────────────────────────▶

2배 증가      1 ─ 2 ─── 4 ─────── 8 ───────────── 16
선형 증가     1 ───────── 11 ───────── 21 ───────── 31
```

2배 증가 방식은 한 번의 재할당 비용은 크지만 재할당 횟수가 로그 수준으로 줄어 `push_back`의 평균 O(1) 성능을 얻습니다. 선형 증가는 사용하지 않는 여유 공간을 줄일 수 있지만, 원소 수가 커질수록 전체 복사·이동이 자주 발생하여 누적 비용이 O(n²)에 가까워집니다.

### 표준 구현과의 비교 계획

정식 비교에서는 `MyVector`와 `std::vector`에 동일한 원소를 추가하며 다음 항목을 측정합니다.

- 입력 크기별 `push_back` 총 실행 시간
- 증가 계수별 재할당 횟수와 실행 시간
- `reserve` 사용 전후의 실행 시간
- 단순 복사 가능 타입과 비단순 타입의 원소 이동 비용

측정 결과는 `Result/`에 원본 데이터와 그래프로 저장합니다. 현재는 측정 데이터가 없으므로 이론적 분석만 기록했으며, 실제 수치가 준비된 뒤 비교 그래프와 측정 환경을 함께 추가합니다.
